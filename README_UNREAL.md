## 1. 폴더 구조

```
UnderwaterHideSeek_Assets/
├── README_UNREAL.md          ← 이 문서
├── SM_*.fbx                  ← 언리얼로 가져올 정적 메시 (모델 1개 = 파일 1개)
├── SK_*.fbx                  ← 캐릭터 (뼈대·애니메이션 포함)
├── Textures/                 ← 괴물용 구운 텍스처 (T_<이름>_BaseColor/Normal/Roughness/Emissive.png, 4096)
└── Source/
    ├── DiveGear_Scene.blend  ← 모든 모델이 들어 있는 작업 씬
    ├── <모델명>.blend         ← 모델별 원본 (원점, 실제 크기)
    └── _tools/
        ├── mk.py             ← Blender 제작·FBX 내보내기 도구
        └── split_models.py   ← 모델별 .blend 분리 도구
```

- **FBX를 고치려면 반드시 `Source`의 .blend를 고친 뒤 다시 내보내세요.** FBX를 직접 수정하면 다음에 다시 내보낼 때 덮어써집니다.

## 2. 모든 에셋 공통 규칙

| 항목 | 규칙 |
|---|---|
| 크기 | 실제 크기(1 Blender m = 100 Unreal cm). **Import Uniform Scale = 1.0** 그대로 두세요. |
| 메시 구성 | FBX 1개 = **Static Mesh 1개**. 부품은 하나로 합쳐져 있고, 재질만 슬롯으로 나뉩니다. 움직여야 하는 부분(문, 해치, 레버)은 **별도 FBX**로 분리돼 있습니다. |
| 앞 방향 | 방향이 있는 에셋은 **+X가 앞**입니다. |
| 축 변환 | FBX는 Blender 기본 설정(-Z Forward, Y Up)으로 내보냈습니다. 언리얼의 **Convert Scene = 켜기(기본값)**, **Force Front XAxis = 끄기**로 가져오세요. X·Z는 같고 **Y는 부호가 반대**입니다(Blender −Y = Unreal +Y). 처음 가져온 뒤 방향을 한 번 확인하세요. |
| 소켓 | 상호작용 지점, 조명 위치, 경첩 위치가 **Static Mesh 소켓(`SOCKET_이름`)**으로 들어 있습니다. 좌표를 외울 필요 없이 소켓 이름으로 붙이세요. 축 변환도 자동으로 적용됩니다. |
| 기준점(Pivot) | 에셋마다 다릅니다. [5. 에셋별 유의사항](#5-에셋별-유의사항)을 확인하세요. 움직이는 부품은 **기준점 = 경첩(회전축)**입니다. |
| 이름 | 메시는 `SM_<이름>`, 재질은 `M_<에셋>_<부위>`. |
| UV | UV0 = 자동 펼침(텍스처는 아직 없음). UV1 = `Lightmap` 채널. |
| 콜리전 | **들어 있지 않습니다.** [3-3](#3-3-콜리전)대로 언리얼에서 설정하세요. |
| 애니메이션·뼈대 | 없습니다. 전부 Static Mesh이고, 문이나 레버는 언리얼에서 회전시켜 움직입니다. |

### 권장 임포트 설정

- Skeletal Mesh: **끄기** / Combine Meshes: 켜기
- Import Uniform Scale: **1.0** / Convert Scene: **켜기** / Force Front XAxis: **끄기**
- Normal Import Method: **Import Normals**
- Material Import: **Create New Materials** (같은 이름의 재질은 재사용됨, 예: `M_Part_*`, `M_Sub_*`)
- Auto Generate Collision: **끄기** (아래 3-3대로 직접 설정)
- 소켓은 Static Mesh 에디터의 **Socket Manager**에서 확인할 수 있습니다.

## 3. 언리얼에서 꼭 손봐야 하는 것

### 3-1. 재질 (FBX로 옮겨지지 않는 효과)

FBX에는 기본 색, 금속성, 거칠기만 들어갑니다. 아래 효과는 언리얼 재질에서 직접 설정하세요.
켜고 끄는 발광 재질은 **Emissive 세기를 Scalar Parameter(`EmissiveStrength`)로 만들고 Material Instance로 쓰면** 블루프린트에서 조절할 수 있습니다.

| 효과 | 해당 재질 | 언리얼에서 할 일 |
|---|---|---|
| 발광 (켜고 끄기) | `M_DiveLight_LED`, `M_SubIn_CeilingLight`, `M_SubIn_Screen`, `M_Sub_Lamp`, `M_Sub_Warning` | Emissive + `EmissiveStrength` 파라미터 |
| 발광 (상시) | `M_Battery_Glow`, `M_Part_GlowBlue`, `M_Part_Glass`, `M_SubIn_ButtonGreen`, `M_Reg_GaugeFace` | Emissive 연결 |
| 투명·유리 | `M_DiveLight_Glass`, `M_Sub_Glass` (잠수함 돔) | Blend Mode = Translucent, **Two Sided 켜기** |
| 반사 렌즈 | `M_Mask_Lens` | 어두운 반투명 또는 반사가 강한 재질 |

### 3-2. 조명

- 모든 빛은 **모델만 있고 실제 라이트는 없습니다.** 아래 소켓에 라이트 컴포넌트를 붙이세요.
  - 손전등: `SM_DiveLight` → `SOCKET_Beam` (Spot Light, [6-2](#6-2-손전등-onoff-bp_divelight) 참고)
  - 잠수함 전조등: `SM_Submarine` → `SOCKET_Headlight_1`~`4` (Spot Light, +X 방향)
  - 선실 천장등: `SM_Sub_Interior` → `SOCKET_CabinLight_1`~`3` (Point Light 또는 아래를 향한 Rect Light)
- 물속 분위기(푸른 안개, 빛줄기)는 언리얼에서 Exponential Height Fog + Volumetric Fog로 만드세요.

### 3-3. 콜리전

| 에셋 | 권장 설정 | 이유 |
|---|---|---|
| `SM_Submarine`, `SM_Sub_Interior` | **Use Complex Collision As Simple** | 해치 통로와 선실 안을 걸어 다녀야 해서 단순 박스로는 막혀버림 |
| `SM_Sub_HatchLid`, `SM_Sub_BayDoor`, `SM_Sub_LockerDoor` | 단순 박스 콜리전 1개 | 움직이는 문이라 가벼운 콜리전이 좋음 |
| `SM_Sub_PowerLever` | 콜리전 없음 (상호작용은 트리거로) | |
| 수집 아이템 (배터리, 수리 부품) | 단순 박스나 구 | 줍기만 하면 됨. 전선 릴은 굴러갈 수 있으니 회전 잠금 |
| 장착 장비 (산소통, BCD, 마스크, 오리발, 레귤레이터, 손전등) | No Collision | 캐릭터에 붙이는 용도 |

- 술래 NPC가 잠수함 안까지 쫓아와야 하면 선실 바닥에 **NavMesh Bounds Volume**을 따로 깔아야 합니다(통로가 좁아서 Agent Radius를 작게, 약 30cm 이하).

### 3-4. 장착과 움직임

- 다이버 장비는 **굳은 모양의 Static Mesh**라 캐릭터가 움직여도 휘지 않습니다. 몸을 따라 움직여야 하면 캐릭터 뼈대에 맞춰 리깅해야 합니다.
- 소켓에 붙일 때는 각 에셋의 기준점과 앞 방향(+X)을 기준으로 맞추세요.

### 3-5. 성능

- 수집 아이템은 삼각형 1,000~3,000개입니다.
- **손전등(약 15,000개)**, **BCD(약 12,600개)**, **잠수함 외부(약 15,300개)**는 무거운 편이라 **LOD나 Nanite**를 권장합니다. 다만 Nanite는 반투명 재질(돔 유리)에는 적용되지 않습니다.

## 4. 잠수함 구성

잠수함은 **6개 FBX를 조립**해서 씁니다. 외부와 내부는 **기준점이 같아서**(착지 스키드 바닥 중앙) 같은 위치에 겹쳐 놓기만 하면 맞습니다. 움직이는 부품은 소켓에 붙이면 경첩 위치에 정확히 들어갑니다.

| FBX | 역할 | 붙이는 위치 | 기본 상태 | 여는 방향 (언리얼 기준) |
|---|---|---|---|---|
| `SM_Submarine` | 외부 선체 (속이 빈 선체, 해치 통로, 외부 장비, 고장 부위) | 액터의 Root | — | — |
| `SM_Sub_Interior` | 선실 내부 전체 (바닥, 사다리, 조종석, 콘솔, 산소 충전대, 사물함, 전원 패널, 조명, 돔 안쪽 면) | Root에 위치 (0,0,0) | — | — |
| `SM_Sub_HatchLid` | 탈출 해치 뚜껑 (바깥 손잡이 바퀴, 안쪽 손잡이) | `SM_Submarine` → `SOCKET_HatchHinge` | 닫힘 | **Pitch +110°** (앞쪽 가장자리가 들림) |
| `SM_Sub_BayDoor` | 배터리 정비 칸 문 | `SM_Submarine` → `SOCKET_BayDoorHinge` | 닫힘 | **Roll 약 110°**, 바깥 위쪽으로 열림 |
| `SM_Sub_LockerDoor` | 숨는 사물함 문 | `SM_Sub_Interior` → `SOCKET_LockerDoorHinge` | 닫힘 | **Yaw +100°** |
| `SM_Sub_PowerLever` | 메인 전원 레버 | `SM_Sub_Interior` → `SOCKET_PowerLeverPivot` | 위로 세운 상태 = **OFF** | **Pitch −60°** = ON (선실 쪽으로 내림) |

> 회전 부호는 축 변환 때문에 반대로 나올 수 있습니다. 처음 한 번 에디터에서 돌려 보고, 열리는 방향이 반대면 부호를 바꾸세요.

- Wrecked에는 재질이 추가됩니다: `M_Sub_HullWrecked`(바랜 노란 페인트), `M_Sub_RustPatch`, `M_Sub_RustHeavy`, `M_Sub_RustStreak`, `M_Sub_BarnaclePurple`, `M_Sub_BarnaclePink`, `M_Sub_BarnacleOpening`, `M_Sub_MetalCorroded`, `M_Sub_InteriorWallWrecked`, `M_Sub_LampBroken`, `M_Sub_Barnacle`, `M_Sub_Algae`, `M_SubIn_PanelWrecked`, `M_SubIn_FloorWrecked`, `M_SubIn_ScreenBroken`, `M_SubIn_LightOff`, `M_SubIn_Water`(물웅덩이 — 언리얼에서 거칠기 낮은 반사 재질로), `M_SubIn_Foam`, `M_SubIn_Soot`, `M_SubIn_Silt`, `M_SubIn_Mold`, `M_SubIn_WaterLine`.
- Wrecked 선실은 바닥에 넘어진 물건이 많아서 **Complex Collision을 쓰면 다이버가 걸릴 수 있습니다.** 소품(난파선 내부 탐험)으로 쓸 때는 바닥만 단순 콜리전으로 두는 것을 권장합니다.
- Repaired의 기어·퓨즈는 소켓에 **X축 −90°** 돌려 붙인 모습입니다(기어 축이 Y 방향, 퓨즈 핀이 상자 안쪽). 게임 진행용에서 같은 부품을 소켓에 붙일 때도 이 회전을 쓰세요.
- Wrecked는 따개비·해초 때문에 삼각형이 많으니 멀리서 보이는 소품이면 LOD를 만드세요.

- **경계**: 깨진 유리처럼 지그재그로 나뉜 두께 2cm 아크릴 껍데기. 깨진 단면은 따로 재질(`M_DomeShard_Edge`, 약간 불투명한 밝은 유리)이라 윤곽이 잘 보입니다.
- **재질**: `M_DomeGlass_Acrylic`은 **Translucent + Two Sided**. 줍는 아이템으로 눈에 띄게 하려면 Emissive를 약하게 넣거나 작은 Point Light를 두세요.
- **블루프린트 권장**:
  - `BP_Submarine`에 Static Mesh 컴포넌트 `DomeShard_1~6`를 각 소켓에 붙여 두고, 처음엔 **Visible = false**.
  - 조각을 주워 잠수함에서 상호작용하면 **모은 개수 `ShardCount`를 1 올리고 조각 하나를 보이게** 합니다. 어떤 조각을 주웠든 순서대로(1→6) 켜는 방식이 간단합니다. 특정 조각을 특정 자리에 끼우게 하려면 조각 번호와 소켓 번호를 맞추세요.
  - `ShardCount == 6`이면 돔 완성 → 수리 목표 하나 완료. 필요한 개수를 줄이고 싶으면(예: 4개) 남은 조각은 완성 순간 한꺼번에 켜는 연출도 가능합니다.
  - 다 모인 뒤 `SM_Submarine_Repaired`로 메시를 바꾸면 조각 컴포넌트는 숨기세요(수리된 버전에는 매끈한 완성 돔이 들어 있음).
- **다른 버전 — 유리 가루 `SM_GlassPowder`** (40.6 × 43.5 × 9.4cm, 6,370 삼각형, 기준점 바닥 중앙): 고운 유리 가루 더미 위에 각진 결정 모양 알갱이(0.3~1.8cm) 약 390개와 납작한 유리 부스러기가 섞여 있습니다. 조각처럼 정해진 자리에 끼우는 방식이 아니라 **모은 양을 세는 자원형**입니다. 예: 가루 더미 N개를 모아 잠수함에서 "녹여 붙이기" 상호작용 → 돔 완성(조각 컴포넌트 6개를 한꺼번에 켜거나 수리된 버전 돔을 보여줌). 조각 방식과 섞어서 "조각 4개 + 가루 2개"처럼 써도 됩니다.
  - 재질: `M_GlassPowder_Fine`(뿌연 흰 가루, 불투명에 가깝게), `M_GlassPowder_Grain`(푸른 투명 알갱이 — Translucent 또는 Masked + 높은 Specular로 반짝이게), `M_GlassPowder_Chip`.
  - 작고 납작해서 바닥에 묻히기 쉬우니 줍기 판정을 크게 하고, 약한 Emissive나 반짝임(Niagara 스파클)을 더하면 잘 보입니다.
- `SM_DomeGlass`(완성된 돔 하나)는 이제 **수집용이 아니라 참고·연출용**입니다.
- 기본형 크기 변화: 외부 700 → **649cm**(돔 유리가 빠짐), 선실 483 × 294 → **379 × 274cm**(안쪽 돔 면이 빠짐). 기준점은 그대로입니다. 망가진·수리된 버전은 돔이 있습니다(망가진 버전은 금 간 돔). 두 버전도 `SOCKET_DomeShard_*`를 가집니다.

- **게임에서 다이버 색이 안 나올 때 (2026-11-23)**: 원인은 ① 예전 FBX가 텍스처를 **경로로만** 가리켜서(팀원 PC 절대경로 / 옆의 `Textures\`) FBX만 가져오면 텍스처가 안 붙음, ② 다이버 초기 버전(텍스처 없음) 때 생긴 `M_Diver` 재질이 프로젝트에 남아 있으면 언리얼이 **같은 이름 재질을 재사용**해서 다시 가져와도 색이 안 붙음. 해결: 이제 `SK_Diver.fbx`에 **4096 텍스처 4장이 들어 있습니다**(약 30MB). 언리얼에서 ⑴ 콘텐츠 브라우저의 기존 `M_Diver`(와 `T_Diver_*`)를 지우거나 이름을 바꾸고, ⑵ `SK_Diver.fbx`를 다시 임포트(Material Import Method = **Create New Materials**, **Import Textures 켜기**). 그래도 회색이면 `M_Diver`를 열어 `T_Diver_BaseColor` → Base Color, `T_Diver_Normal`(Normal Map, Flip Green) → Normal, `T_Diver_Roughness`(sRGB 끄기) → Roughness, `T_Diver_Emissive` → Emissive Color를 직접 연결하세요.
- **동작 속도 바꾸기**
  - 언리얼(권장, 다시 내보낼 필요 없음): 애니메이션 시퀀스 에셋을 열고 Asset Details → **Rate Scale**(1.0 기본, 1.2 = 20% 빠르게, 0.8 = 느리게). BlendSpace는 샘플마다 Rate Scale, AnimBP의 Sequence Player 노드는 **Play Rate** 핀(예: `현재 속도 ÷ 자연 속도`를 연결하면 이동 속도에 자동으로 맞음), Montage는 `Play Montage`의 **Play Rate**.

  - 손전등(`SM_DiveLight`)만 손에 들게 하려면 스켈레톤에 `hand_r` 소켓을 만들어 붙이세요(손바닥 안, 렌즈가 손가락 방향).

### 적 캐릭터: 블루프린트 권장 구성

## 4-C. 수리·부품 줍기 애니메이션 개선 지침

> 2026-11-09에 만든 `DV_Pickup`, `DV_Repair`, `DV_Install`은 **부자연스럽다**는 판단으로 교체 예정입니다.
> 이 장은 다시 만드는 사람(팀원 또는 AI)이 따라야 할 기준입니다. 아래 순서대로 체크하세요.
> **2026-11-16: 이 지침대로 v2를 만들었습니다**(Blender 키 포즈 방식, 도구는 `Source/_tools/anim_kit.py`, `diver_poses.py`, `build_diver_anims_v2.py`). 언리얼 쪽 마무리(Motion Warping, Two Bone IK, Montage 섹션·Notify)는 아직 하지 않았습니다. 고칠 때도 이 장을 기준으로 하세요.

### 1) 지금 버전이 부자연스러운 이유

| 문제 | 원인 | 고칠 방향 |
|---|---|---|
| 로봇처럼 딱딱함 | 몇 개의 고정 자세 사이를 똑같은 속도 곡선(smoothstep)으로만 보간 | 동작마다 **예비동작 → 본동작 → 따라오는 동작 → 정착**을 따로 잡고, 관절마다 시작 시점을 어긋나게(오프셋) |
| 몸 전체가 한 덩어리로 움직임 | 골반·척추·머리·팔이 같은 프레임에 동시에 출발·도착 | **눈(머리) → 몸통 → 어깨 → 팔꿈치 → 손목** 순서로 2~4프레임씩 늦게 따라가게 |
| 손이 물건·패널에 닿지 않음 | 관절 각도만 돌려서(FK) 손 위치가 정해지지 않음 | 손 목표 지점을 정하고 **IK**로 손을 붙인 뒤 팔을 맞춤 |
| 물속 느낌이 없음 | 지상 동작처럼 멈췄다 섰다 함 | **부력·물 저항**: 느린 가속, 긴 감속, 작은 출렁임, 오리발로 자세 유지 |
| 무게감 없음 | 부품을 들어도 몸에 변화가 없음 | 집는 순간 손이 살짝 내려갔다(무게) 올라오고, 몸이 반동으로 기울어짐 |
| 같은 동작 반복이 기계적 | 수리 반복을 사인파 하나로 만듦 | 2~3개의 서로 다른 작업 동작을 섞고, 사이에 쉬는 자세·고개 확인 넣기 |
| 다리가 의미 없이 고정 | 상체만 움직임 | 손을 뻗을 때 **오리발을 한두 번 저어 위치 보정**, 균형을 위해 반대쪽 다리가 뒤로 |

### 2) 물속 동작의 공통 규칙

- **속도**: 지상보다 1.3~1.5배 느리게. 빠른 동작도 끝은 길게 감속(ease-out을 길게).
- **정지 없음**: 완전히 멈춘 프레임을 두지 말 것. 멈춘 것처럼 보이는 구간에도 몸통이 1~2cm, 1~2° 정도 계속 출렁임(호흡 주기 약 3~4초).
- **중성부력 자세**: 기본은 몸이 약 10~20° 앞으로 기울고 무릎이 굽은 "트림" 자세. 다리는 개구리차기 대기 자세(무릎 약 60~90°, 오리발 끝은 뒤·위쪽).
- **균형 반작용**: 팔을 앞으로 뻗으면 다리는 뒤로, 몸을 숙이면 엉덩이가 뒤로 빠짐. 한 부위가 움직이면 반대쪽이 받쳐 줌.
- **오리발 보정**: 위치를 맞출 때 작은 개구리차기·백킥을 1회(약 12~16프레임) 넣기. 손을 쓰는 동안은 다리를 크게 움직이지 않음(실제 다이버 습관).
- **시선 먼저**: 모든 동작은 고개(마스크)가 먼저 목표를 보고 4~6프레임 뒤 손이 출발.
- **장비 영향**: 등에 산소통이 있어서 몸통을 비틀거나 젖힐 때 범위가 작음(척추 회전 각 30° 이내). 두꺼운 3손가락 장갑이라 손목 움직임이 크고 손가락 동작은 단순.

### 3) 부품 줍기 (`DV_Pickup`) 설계

- **상황**: 부품이 바닥이나 선반 위, 캐릭터 앞 약 50~80cm, 아래 약 40~70cm에 있음.
- **길이**: 약 2.5~3초 (60~72f, 24fps).

| 구간 | 프레임(24fps) | 동작 |
|---|---|---|
| 1. 발견·조준 | 1~10 | 고개를 숙여 부품을 봄. 몸통은 아직 그대로, 손이 살짝 앞으로 준비 |
| 2. 접근 | 10~24 | 오리발로 작게 한 번 저으며 몸을 앞으로 기울여 머리 쪽이 내려감(골반 회전 40~60°). 무릎이 굽고 오리발 끝이 위로 올라감(균형) |
| 3. 손 뻗기 | 20~32 | 어깨 → 팔꿈치 → 손목 순으로 늦게 출발. 손바닥이 부품 쪽을 향하도록 손목을 돌림. 왼손은 바닥이나 주변을 짚어 몸을 받침 |
| 4. 잡기 | 32~38 | 손이 부품에 닿아 1~2프레임 멈칫 → 손목이 감싸듯 접힘. **Notify `GrabItem` = 손이 닿는 프레임** |
| 5. 들어 올리기 | 38~50 | 무게 때문에 손이 1~2cm 내려갔다가 올라옴. 팔꿈치가 먼저 굽고 손이 몸 쪽으로 |
| 6. 확인·수납 | 50~64 | 부품을 가슴 앞으로 가져와 잠깐 봄(고개 약간 기울임) → 허리 주머니나 BCD 쪽으로 넣는 동작 |
| 7. 복귀 | 64~72 | 몸을 일으키며 기본 떠 있기 자세로. 마지막 10프레임은 길게 감속 |

- **변형 2종 권장**: 바닥에서 줍기(위 표), 눈높이 선반에서 줍기(몸을 숙이지 않고 팔만 뻗는 짧은 버전, 약 1.5초).

### 4) 수리 (`DV_Repair`) 설계

- **상황**: 잠수함 수리 지점(`SOCKET_Repair_*`) 앞. 패널이 가슴~눈 높이, 캐릭터와 약 50~60cm 거리.
- **구성**: 한 개의 반복 대신 **시작 → 작업 반복(여러 동작 섞기) → 끝**으로 나눈 Montage.

| 섹션 | 길이 | 동작 |
|---|---|---|
| `Start` | 약 1초 | 패널을 보며 다가가 **왼손으로 잠수함 손잡이·가장자리를 잡아 몸을 고정**. 다리는 무릎을 굽혀 뒤로 접음(물속에서 몸이 밀리지 않게) |
| `Loop_A` 렌치 | 약 2초 | 오른손으로 렌치를 짧게 3~4번 끊어 돌림(한 번에 60~90°). 돌릴 때마다 팔꿈치·어깨가 따라 들썩이고 몸이 반동으로 아주 조금 밀림 |
| `Loop_B` 힘주기 | 약 1.5초 | 꽉 낀 볼트를 두 손으로 힘주어 돌림. 어깨가 올라가고 몸이 살짝 웅크렸다 풀림 |
| `Loop_C` 확인 | 약 1.5초 | 손을 멈추고 고개를 기울여 들여다봄(헤드램프로 비추는 느낌), 장갑으로 표면을 쓸어봄 |
| `End` | 약 1초 | 왼손을 놓고 몸을 뒤로 빼며 떠 있기 자세로 |

- 진행 바가 차는 동안 `Loop_A → A → B → A → C …`처럼 **무작위 순서로 이어 붙이기**(같은 동작이 연속으로 보이지 않게).
- 수리 지점마다 손 높이가 다르므로(배터리 칸은 낮고, 퓨즈함은 높음) **손 IK 목표를 소켓 위치에 맞추고**, 높이 차이는 몸 전체 위치로 보정.
- 소리·효과 Notify: 렌치 돌릴 때마다 `Ratchet`(딸깍), 힘줄 때 `Strain`(숨소리·거품), 확인 때 `Inspect`.

### 5) 부품 끼우기 (`DV_Install`) 설계

| 구간 | 프레임 | 동작 |
|---|---|---|
| 1. 맞추기 | 1~16 | 두 손으로 부품을 들고 슬롯 앞에서 각도를 맞춤(손목 좌우로 조금씩 흔들며 위치 찾기) |
| 2. 밀어 넣기 | 16~26 | 몸통까지 같이 앞으로 밀며 넣음. 끝에서 걸리는 느낌으로 2프레임 멈칫. **Notify `AttachPart` = 부품이 슬롯에 닿는 프레임** |
| 3. 잠그기 | 26~38 | 손잡이를 90° 돌리거나 손바닥으로 탁 쳐서 고정. **Notify `LockPart`**(딸깍) |

### 6) 제작 방법 (추천 순서)

1. **참고 자료 먼저**: 실제 다이버의 수중 작업 영상(장비 점검, 난파선 작업, 수중 용접)에서 타이밍과 자세를 캡처해 프레임 단위로 메모.

4. **언리얼에서 마무리**:
   - **Motion Warping**으로 동작 시작 시 캐릭터를 수리 지점·부품 앞 정확한 위치로 끌어당김.

## 6. 상호작용 구현 가이드

에셋 쪽 준비(분리된 부품, 경첩 기준점, 소켓)는 끝나 있습니다. 아래는 언리얼에서 블루프린트로 연결하는 권장 방법입니다.

### 6-1. 공통 구조

1. **Blueprint Interface `BPI_Interactable`**을 만들고 함수 `Interact(Instigator: Actor)`, `GetPrompt() → Text`를 둡니다.
2. 플레이어 캐릭터는 카메라 앞으로 짧게(약 150cm) **Line Trace**를 쏘거나, 상호작용 트리거와 겹치면 `E` 키로 `Interact`를 호출합니다.
3. 상호작용 지점마다 **Box Collision(트리거)**을 해당 소켓 위치에 둡니다. 트리거의 Collision Preset은 `OverlapAllDynamic`입니다.
4. 문이나 레버는 **Timeline**(0→1, 0.4~0.8초)으로 상대 회전을 보간합니다.

### 6-2. 손전등 on/off (`BP_DiveLight`)

1. 액터 `BP_DiveLight` 생성 → Static Mesh 컴포넌트에 `SM_DiveLight`.
2. **Spot Light** 컴포넌트를 추가하고 Parent Socket을 **`SOCKET_Beam`**으로 지정합니다(위치·회전 0).
   - 권장값: Inner Cone 12°, Outer Cone 22°, Attenuation Radius 1500~2500cm, 따뜻한 흰색(약 5000K), Cast Shadows 켜기. 물속 빛줄기는 Volumetric Scattering Intensity를 올리고 Volumetric Fog를 켜면 보입니다.
3. `M_DiveLight_LED`를 Emissive 파라미터 재질로 만들고, BeginPlay에서 **Create Dynamic Material Instance**(LED 슬롯)를 만듭니다.
4. 변수 `bIsOn`(Boolean)과 함수 `ToggleLight`를 만듭니다.
   - `bIsOn = !bIsOn`
   - `SpotLight → Set Visibility(bIsOn)`
   - `LED MID → Set Scalar Parameter Value("EmissiveStrength", bIsOn ? 20 : 0)`
   - (선택) 딸깍 소리를 `SOCKET_Switch` 위치에서 재생합니다.
5. 플레이어 입력(예: `F` 키, Enhanced Input Action `IA_ToggleLight`)에서 들고 있는 손전등의 `ToggleLight`를 호출합니다. 캐릭터 손 소켓에 붙여 쓰면 됩니다.
6. (선택) 배터리 시스템: 켜져 있는 동안 배터리 값을 줄이고, 0이 되면 자동으로 끕니다. 남은 양이 적으면 깜빡이게(`EmissiveStrength`와 Intensity를 무작위로 흔들기) 연출할 수 있습니다.

### 6-3. 잠수함 (`BP_Submarine`)

컴포넌트 구성:
```
BP_Submarine
├── Hull           (Static Mesh: SM_Submarine)          ← Root
│   ├── HatchLid   (SM_Sub_HatchLid,  Parent Socket: SOCKET_HatchHinge)
│   ├── BayDoor    (SM_Sub_BayDoor,   Parent Socket: SOCKET_BayDoorHinge)
│   ├── Headlight1~4 (Spot Light,     Parent Socket: SOCKET_Headlight_1~4)
│   └── Trigger_Repair_Battery/Pipe/Gear/Fuse/Prop/Hull, Trigger_Hatch (Box, 각 소켓 위치)
└── Interior       (Static Mesh: SM_Sub_Interior, 위치 0)
    ├── LockerDoor (SM_Sub_LockerDoor, Parent Socket: SOCKET_LockerDoorHinge)
    ├── PowerLever (SM_Sub_PowerLever, Parent Socket: SOCKET_PowerLeverPivot)
    ├── CabinLight1~3 (Point Light,    Parent Socket: SOCKET_CabinLight_1~3)
    └── Trigger_Console/O2Refill/Medkit/LightSwitch/Locker/Ladder, Trigger_Repair_Scrubber/Circuit (Box)
```

권장 상호작용:

| 대상 | 트리거 소켓 | 동작 |
|---|---|---|
| 해치 | `SOCKET_Escape` (밖), `SOCKET_Ladder_Top` (안) | 해치 열기/닫기. 열려 있으면 들어가기·나가기. 모든 수리 완료 후에는 **탈출 지점**. |
| 사다리 | `SOCKET_Ladder_Bottom` ↔ `SOCKET_Ladder_Top` | 두 소켓 사이를 오르내리는 이동(또는 Climb 상태). |
| 정비 칸 문 | `SOCKET_BayDoorHinge` 근처 | 문 열기. 열린 상태에서만 배터리 장착 가능. |
| 수리 지점 8곳 (외부 6, 내부 2) | `SOCKET_Repair_*` | 맞는 아이템을 들고 있으면 장착(진행 바 + 수리 시간). 장착하면 해당 아이템 메시를 소켓 위치에 보이게 하고, 근처 경고등을 끕니다. 모든 수리 지점 옆에 경고등(`M_Sub_Warning`)이 있습니다. 판마다 8곳 중 일부(예: 5곳)만 무작위로 고장 내면 반복 플레이에 변화가 생깁니다. |
| 메인 전원 레버 | `SOCKET_Interact_PowerLever` | 필요한 수리를 모두 끝낸 뒤에만 ON 가능. ON → 천장등·화면·전조등 켜짐, 경고등 꺼짐. |
| 콘솔 | `SOCKET_Interact_Console` | 전원 ON 상태에서 시동 → 탈출 시퀀스 시작. |
| 사물함 | `SOCKET_Hide_Locker` | 문 열고 들어가 숨기(데바데 사물함과 같은 방식). 술래가 수색하면 발각. |
| 산소 충전대 | `SOCKET_Interact_O2Refill` | 플레이어 산소 충전 (전원 ON일 때만 등의 조건 가능). |
| 구급상자 | `SOCKET_Interact_Medkit` | 회복 (사용 횟수 제한 권장). |
| 조명 스위치 | `SOCKET_Interact_LightSwitch` | 선실 천장등 on/off (숨을 때 끄는 전략 요소). |
| 조종석 | `SOCKET_Seat_L/R` | 앉기 (탈출 연출용). |

- 진행 상황(수리 4곳, 전원 상태)은 멀티플레이를 고려해 **GameState**나 잠수함 액터의 **Replicated 변수**에 두세요.
- 경고등·천장등·화면은 재질 파라미터(`EmissiveStrength`)로 켜고 끕니다. 경고등을 초록으로 바꾸려면 `EmissiveColor` 파라미터도 만들어 두세요.
